# espero audit, 2026-10-27

Read-only review of the whole package, the research scripts and the tests at commit
ecf8663. Baseline: 283 tests pass, ruff clean, no secrets tracked, every journal
database gitignored. Nothing was changed; no running loop or `.db` file was touched.
"Confirmed" means reproduced with a snippet on a temporary journal or checked line by
line against the code.

## A. Hurts the running forward tests now (fix first)

All seven loops were alive at the time of the audit.

| # | Where | Defect | Effect | Status |

| A2 | cli.py `_degen_loop` step; cli.py `_carry_loop` with carry_paper.settled_rows | Bars/rows are fetched only for the current universe (degen: hourly top-60; carry: daily top-20). | A held coin that drops out of the universe gets no stop, trail, target, time stop or funding again and blocks a slot. ## B. Live-trading safety (live is off; fix before it is ever enabled)

No path sends a real Coinbase order without both `ESPERO_ALLOW_LIVE=1` and `--confirm-live`, and Hyperliquid signing cannot reach mainnet.

- **B1 live.py ~101: the KILL file and the daily-loss halt return before the stop check.** An open position loses its stop exactly when things go wrong; test_live.py enshrines it.
- **B2 live.py ~64: the daily-loss baseline is memory-only.** A restart resets the halt.
- **B3 cli.py ~559: `espero live` takes no JournalLock.** Two loops on live.db would both trade.
- **B4 broker.load_env: `ESPERO_ALLOW_LIVE` is accepted from .env.** Uncommenting it once leaves `--confirm-live` as the only gate.
- **B5 broker.load_env parser:** `export K=v` becomes key "export K"; inline comments stay in quoted values; multi-line PEMs keep only the first line; base64 lines ending in `=` become env vars named after key material.
- **B6 notify.py with data.FetchError: the webhook URL, a bearer secret, is written to daily.log on failure.** POSTs are also retried, so alerts can duplicate.
- **B7 runner.py: the daily job never calls `load_env`.** The webhook from .env is never read under launchd, so alerts are silently off.
- **B8 live.py/broker.py: dry-run never debits cash** (equity 525 after a 25 buy), so the loss halt cannot fire in dry run and the dashboard total is inflated.
- **B9 the Coinbase Ack has no filled size;** size is estimated as notional/close, so a later sell can exceed the holding and be rejected.
- **B10 runner.py: dry-run and preflight runs set `last_success` in health.json,** hiding a failing real job.

## C. Testnet mirror (built last; not yet switched on)

- **C1 hl_exchange.py ~120: orders and fills are read for the signing key's address.** For an API (agent) wallet the orders belong to the master account, so reads come back empty, every order is marked cancelled after the grace, and paper closes leave the testnet shorts open. `HL_WALLET_ADDRESS` should be the account address.
- **C2 the mirror prices orders from mainnet but posts them to the testnet book.** Whether an ALO rests, crosses or fills then reflects the testnet-mainnet price gap, not maker fill probability, so as built it cannot validate #12's maker assumption. Price from the testnet book's own bid/ask instead.
- **C3 orphan paths:** a part-filled open's remainder is never cancelled; a rejected or never-filled close is never retried; an order accepted but timed out is recorded with no oid.

## D. Research statistics

No published PASS/FAIL verdict flips on any of these, but two make reported numbers wrong.

- **D1 factor_eval.summarize: t = ICIR·√n on overlapping h-day forward returns.** Under a null with h=5 the reported t has sd 2.2 instead of 1. MF composite: naive t 8.1, Newey-West 4.5-5.0, non-overlapping 3.2. The "expected best null t" shown beside it is also too low. LEADLAG's t of 13-17 are inflated the same way.
- **D2 carry.metrics: Sharpe on hourly marks,** which carry two-venue basis noise (lag-1 autocorrelation −0.5). Daily-resampled Sharpe is about 4× higher (#12: 7.2 vs 1.77). The criterion depends heavily on sampling frequency.
- **D3 research/carry.py: today's top-20 by open interest applied to history.** Disclosed, but this survivorship favours positive funding and #12 is the pass it could inflate. The forward test is the only control.
- **D4 tsmom/xs20/momentum: lookback is one bar short** (`iloc[-LOOKBACK]` gives 251 days, not 252). TSMOM passed narrowly; its input CSVs are not on disk, so the effect could not be checked.
- **D5 carry.simulate: the 30-day time stop exits even when the coin still qualifies,** then re-enters the same hour (4 of 11 time exits in #12). The pre-registration says "without re-qualifying". Conservative: fixing it improves results.
- **D6 lp_sim.py: `net` subtracts rewards that were never added to cash.** The trading-P&L column in LP_NOTES is $12.48 too low per row; totals are right.
- **D7 leadlag.py: `MIN_TRAIN=720` is never passed,** so 180 h is used against the pre-registered 30 days.
- **D8 backtest.metrics hardcodes daily bars** (√365, len/365.25) though the CLI accepts any bar size.
- **D9 carry backtest: one missing hour blanks the trailing average for 168 h** and forces a no_data exit, while the paper book uses `tail(168)`.

## E. Smaller defects

- venues.py: Hyperliquid `funding_bps_8h=3.0`, but its own comment (0.01%/8h) and the live idle rate (10.9%/yr) mean 1 bp. No running loop uses this venue.
- data.fetch: Coinbase's `end` is inclusive, so hourly/daily fetches cache an unclosed last candle (recent_closed_bars already drops it).
- fast.py: after a feed error the previous snapshot is fed again, so paper orders fill twice on the same prints; also each resting order consumes the full printed volume independently.
- fast.py: a failed candle fetch leaves the old signal live; decline is recreated on the next tick; `stale_feed_s` and `max_inventory_notional` are display only.
- execution.PaperExchange: cash/inventory checked per order, ignoring other resting orders and fees (cash can go negative, inventory short).
- degen.py: the chandelier high-water includes the entry bar after a restart but not before; `_day_pnl` (degen and paper) uses the wall clock, so the daily cap never fires in replay.
- paper.compare_venues: the fees total misses exit fees from stops and targets.
- paper.py: sizing uses `RiskLimits.stop_pct`, exits use `PaperConfig.stop_pct`; they can disagree.
- dashboard.py: no HTML escaping; `render()` calls Yahoo, so `daily --dry-run` and a unit test touch the network.
- `carry status` on a mistyped path creates a fresh $500 book.

## F. Test gaps

- No test covers the paper SELL path meeting a stop (A5), a crash part-way through a bar (A7), or the loop functions in cli.py at all (A1, A2, A6).
- The carry equivalence test cannot catch A2-A4: it never changes the universe, skips hours, or returns an empty candle.
- test_live.py asserts B1's stop suppression as correct; the `--confirm-live` mapping is untested.
- test_reference.py tolerances are 1-2 percentage points, against "pinned to four decimals" in pyproject.
- The mirror's fake exchange shares one address for signer and account, so C1 cannot show up.

## Suggested order

1. One shared `run_loop(step)` with try/except, logging and backoff, used by every loop, plus launchd KeepAlive for the forward tests (A1).
2. Always fetch held coins as well as the universe (A2); treat NaN rows as missing (A4); guard the paper SELL path (A5).
3. Feed every fresh bar through `on_bar` / `on_cycle` (A6) and backfill missed carry hours from fundingHistory (A3).
4. One SQLite transaction per bar, or cash stored with each fill (A7).
5. Before turning the mirror on: account address and testnet-book pricing (C1, C2).
6. Newey-West t-stats and daily Sharpe as extra columns in the next results, labelled as a correction, without rerunning verdicts (D1, D2).

Fixes 1-4 change no strategy parameter. A3 and A8 do change what the carry books
record from the fix date on, so the forward-test result should note the date.
